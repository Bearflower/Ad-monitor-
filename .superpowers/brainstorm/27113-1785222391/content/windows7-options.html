Windows 7 兼容路径评估

目标是保持系统可靠、安全，并避免为了旧系统牺牲紫鸟 CLI 和分析能力。

推荐 A

Mac 作为主机，Win7 只访问网页

SQLite、紫鸟 CLI、定时任务和分析都留在 Mac。Win7 通过局域网打开 Web 前端，进行费用、出资、提款、成本与分润维护。

改造量：小

风险：Win7 浏览器本身已过时，只适合受控内网。

可行 B

升级 Windows 后整体迁移

先把机器升级到受支持的 Windows 10/11，再适配路径、任务计划程序、服务管理、安装包、备份与防火墙。

改造量：中等

优势：可以成为新的完整主机。

不推荐 C

强行让完整系统运行在 Win7

需把 Python 3.11 代码回退到 3.8、重写类型语法，寻找非官方 Node 版本，并绕开紫鸟 CLI 的 Node ≥18 要求。

改造量：大

风险：安全、TLS、浏览器、依赖和紫鸟升级随时失效。

如果迁移到受支持 Windows，需要的正式改造

  • 把 macOS launchd 调度替换成 Windows Task Scheduler 或 Windows Service。
  • 消除 /Users、.venv/bin、Library/Application Support 等 Mac 固定路径。
  • 增加 Windows 路径、进程、字符编码、文件锁和防火墙测试。
  • 制作 PowerShell 安装/升级/备份脚本，并验证紫鸟浏览器与 CLI。
  • 为 SQLite 增加单实例写入、自动备份和异常恢复。
