# README 操作与维护文档设计

## 目标

将项目 README 重构为同一份可持续维护的中文文档：

- 前半部分面向经营者，能够完成安装、日常采集、成本维护、对账和看板操作。
- 后半部分面向维护者，能够理解架构、数据口径、安全门禁、测试和故障处理。
- 所有示例以当前 macOS + SQLite + 紫鸟 CLI 的真实部署为准。

## 文档结构

1. 项目定位与当前运行状态。
2. 五分钟启动和环境配置。
3. 每日经营操作流程。
4. 订单、SKU 成本和履约方式。
5. 广告采集、利润分析和报告。
6. 三日对账与上线门禁。
7. 飞书审批和广告写入安全边界。
8. 本地看板、定时任务和备份恢复。
9. 系统架构、模块职责和数据口径。
10. 开发测试、故障排查和当前上线待办。

## 审批说明

- `FEISHU_WEBHOOK` 用于发送报告和审批卡片。
- 公网 HTTPS 回调当前暂缓现场启用。
- 回调只更新批准或拒绝状态，不自动触发广告修改。
- 当前实现要求公网适配层为请求生成 `X-Adwatch-Timestamp`、
  `X-Adwatch-Nonce` 和 `X-Adwatch-Signature` HMAC 头。
- 真实写入还必须由独立执行命令触发，并通过审批有效期、状态漂移、
  熔断、现场选择器、Live 总开关和精确允许清单检查。
- README 不把“回调代码已存在”描述为“现场已经上线”。

## 上线状态表达

README 将待办拆成三类：

- 当前推进：Shadow 对账、回滚演练、选择器激活、三日对账、Live 精确白名单。
- 等待真实业务数据：TikTok 有数据 Campaign 验收。
- 暂缓或可选：飞书公网回调、平台官方 API OAuth。

不得用模拟数据、空 Campaign 或手工设置状态冒充现场验收完成。

## 验证与发布

- 核对 README 中的命令均存在于 CLI 参数解析器。
- 核对环境变量均存在于 `.env.example` 和 `Settings`。
- 运行全量 pytest、Ruff 和 `git diff --check`。
- 仅提交 README 与本设计文档，不纳入用户未跟踪文件。
- 将测试通过的本机 `main` 直接推送到已配置的 `origin/main`。
