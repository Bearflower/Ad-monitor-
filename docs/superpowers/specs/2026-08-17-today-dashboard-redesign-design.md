# 今日经营首页精简改版设计

日期：2026-08-17

## 1. 背景

当前“今日经营”首页同时承载平台指标、本月经营、年度经营、数据来源、Campaign 与 SKU 明细、7/14/30 天趋势、采集质量、审批执行、异常告警和策略建议。多个模块重复呈现相同经营数字或状态，页面纵向过长，用户难以快速判断“今天经营得怎样”和“现在需要处理什么”。

本轮采用“经营决策台”结构与“清透靛蓝”视觉风格，在不改变后台数据口径和业务逻辑的前提下，重组首页信息层级并减少重复内容。

## 2. 目标

- 首屏直接回答四个问题：销售额、广告消耗、综合 ROAS、预估净利润。
- 将异常、建议和待审批事项合并为一个可行动的待办区域。
- 同类趋势只展示一次，取消 7、14、30 天三张重复表格。
- 低频明细和运行信息保留可访问性，但默认不占据首屏。
- 延续 AdWatch 的靛蓝识别色，同时降低渐变、阴影和卡片堆叠造成的视觉噪音。
- 保持桌面和移动端可读、可操作且无页面级横向滚动。

## 3. 非目标

- 不修改经营、利润、ROAS、审批或采集的数据口径。
- 不新增数据库表、迁移、外部依赖或前端框架。
- 不重做其他二级页面；本轮只调整 `/` 今日经营首页。
- 不新增趋势周期切换、拖拽布局或个性化配置。

## 4. 页面信息架构

首页从上到下分为六个区域。

### 4.1 顶部栏与导航

- 页面主标题改为“今日经营”。
- 标题下显示数据日期、当前筛选范围和最近数据状态。
- “真实数据/模拟数据”保留为状态标识。
- 导航保持现有链接语义；首页视觉上突出当前页，低频入口允许在窄屏通过横向导航自身滚动访问，不造成页面级溢出。
- 提供“查看月度经营账”次级链接，不再在首页重复展示整块年度经营数据。

### 4.2 紧凑筛选栏

- 默认显示日期、平台和店铺。
- Campaign 与 SKU 放入原生 `details` 的“更多筛选”区域。
- 保留 GET 查询参数和既有筛选能力。
- “应用筛选”是筛选区唯一主要按钮。

### 4.3 四项核心指标

首页统一展示以下四项聚合指标：

1. 今日销售额：筛选范围内各平台 GMV 合计。
2. 广告消耗：筛选范围内各平台广告消耗合计。
3. 综合 ROAS：总 GMV 除以总广告消耗；广告消耗为零时显示 `N/A`。
4. 预估净利润：筛选范围内已就绪的平台净利润合计；存在关键输入缺口时明确显示“待补数据”，不把缺失值当作零。

四项指标下方以紧凑平台对比行展示 Shopee 和 TikTok 的 ROAS、消耗与净利润，不再为每个平台重复渲染一整套大型 KPI 卡片。

### 4.4 趋势与今日待办

桌面端使用两列布局：左侧约三分之二为 14 天经营趋势，右侧约三分之一为“今天需要处理”。移动端上下排列。

- 趋势只使用现有 14 天数据，展示日期、消耗、GMV、ROAS 和净利润。
- 首页不再输出独立的 7 天和 30 天趋势表格。
- “今天需要处理”合并异常告警、策略建议和待审批事项。
- 顺序为：高严重度异常、其他异常、待审批、策略建议。
- 空状态显示“今天暂无待处理事项”，不渲染空白列表。
- 每条待办保留类型、对象、原因或提示；能够链接到现有二级页的事项提供对应入口。

### 4.5 平台与商品明细

- Campaign 与 SKU 表格放入默认收起的“平台与商品明细”原生折叠区。
- 表格保留平台、店铺、Campaign、SKU、ROAS 和净利润字段。
- 宽表仅在自己的容器内滚动，不产生页面级横向滚动。
- 没有数据时显示带说明的空状态。

### 4.6 数据与运行状态

将以下低频内容合并到默认收起的“数据与运行状态”区域：

- 利润输入来源与覆盖情况。
- 采集运行质量。
- 执行状态。

审批数量已经进入“今天需要处理”后，不在该区域再次显示同一摘要。利润来源的详细 lineage 继续使用内层原生折叠项，保证信息可审计但不默认铺开。

## 5. 视觉规范

采用“清透靛蓝”方向：

- 页面背景使用浅灰蓝纯色，移除大面积背景渐变和固定背景效果。
- 主色保留靛蓝，主要用于当前导航、主要按钮、焦点环和趋势主线。
- 页面标题使用深色实字，不再使用渐变裁切文字。
- 卡片使用白色表面、浅边框和一档轻阴影；移除悬浮时的大幅上移和浓重彩色阴影。
- 圆角控制在统一的小、中两档，避免每层容器都使用大圆角。
- 经营数字采用等宽数字特性；正负结果同时通过符号、文字和颜色表达，不仅依赖颜色。
- 动效只用于 150–250ms 的颜色、阴影和展开状态反馈，并尊重 `prefers-reduced-motion`。

## 6. 响应式与无障碍

- 桌面端最大内容宽度保持约 1200px。
- 四项指标在桌面端为四列，在中小屏为两列，在极窄屏按内容需要变为单列。
- 趋势与待办在窄屏改为单列。
- 交互目标最小高度 44px，焦点状态清晰可见。
- 保留跳到主要内容链接、语义标题层级、表格表头和原生表单标签。
- 折叠区域使用 `details/summary`，不使用只能点击的非语义容器。
- 模拟数据、待补数据、异常和成功状态均提供可读文本。

## 7. 数据流与实现边界

`render_dashboard` 继续从 `ReportReadModel.dashboard(data_date)`、`OperatingStatementService` 和现有汇率服务读取数据。本轮只在展示层进行聚合、排序和 HTML 结构调整。

- 平台聚合指标从筛选后的 `snapshot.platforms` 计算。
- 趋势读取 `dashboard_snapshot.trends[14]`。
- 待办由 `snapshot.alerts`、`snapshot.recommendations` 和审批计数组装。
- Campaign/SKU、利润来源、采集运行记录和执行计数继续使用现有数据对象。
- 所有来自数据库或查询参数的文本继续经过 HTML 转义。
- 缺失值沿用明确的 `N/A` 或“待补数据”语义，不隐式补零。

不引入客户端数据请求或新的 JavaScript 状态管理；页面保持服务端渲染和依赖最小化。

## 8. 异常与空状态

- 无平台数据：四项指标显示明确空状态，平台对比行不生成虚假零值。
- 无趋势数据：趋势区域显示“暂无 14 天趋势数据”。
- 无待办：显示“今天暂无待处理事项”。
- 无 Campaign/SKU：折叠区显示当前筛选范围无明细。
- 数据来源不完整：核心利润指标和来源详情同时显示具体待补含义。
- 非法查询参数继续由现有 HTTP 层返回相应错误，不在视图层吞掉异常。

## 9. 测试与验收

自动测试覆盖：

- 首页仍对数据库内容和查询参数正确转义。
- 平台筛选继续过滤聚合指标、平台对比行和明细。
- 页面包含四项聚合指标与 14 天趋势。
- 页面不再渲染独立的 7 天和 30 天趋势标题。
- 异常、建议和审批被归入统一待办区，不重复显示审批摘要。
- Campaign/SKU 和数据运行信息位于语义化折叠区域。
- 模拟数据、真实数据和利润缺失状态保持正确。
- 既有 Dashboard 路由与 JSON 输出不受影响。

视觉验收覆盖 1440px、1024px、768px 和 375px：

- 页面无横向溢出。
- 首屏层级清晰，四项指标和待办优先于低频详情。
- 移动端指标、筛选、趋势和待办按预期换行。
- 键盘可访问筛选控件、导航和所有折叠区域。

## 10. 完成标准

- 首页采用“经营决策台”结构和“清透靛蓝”视觉。
- 7/14/30 天重复趋势、本月/年度大块经营摘要和重复审批状态已从首页精简或合并。
- 原有数据能力仍可通过核心区域或折叠详情访问。
- Dashboard 相关自动测试通过，页面在目标宽度完成本地视觉检查。
