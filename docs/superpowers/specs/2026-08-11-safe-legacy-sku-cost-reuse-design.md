# 旧 SKU 成本安全继承与待补缺口收敛设计

## 目标

保留 Seller SKU 防串成本能力，同时让能够证明为同一商品的历史成本自动覆盖新采集到的真实 Item/Model 身份；库存页只把真正需要人工处理的成本缺口作为主清单，避免同一缺口以“单价缺失”和“订单快照缺失”重复呈现。

## 已确认根因

1. 历史 `sku_cost_history` 仍完整存在，店铺别名也能被识别；数据没有丢失。
2. `effective_order_sku_lines` 当前按全部历史 `item_id/model_id` 数量拆分成本键。旧导入的合成 ID、占位 ID 和当前真实 ID 会把同一商品错误拆成多个身份。
3. 某些 Seller SKU 的确被不同商品复用，例如 `Chief` 同时表示 50ml 滚珠和 250ml 喷雾，不能退回到 Seller SKU 全局复用。
4. 库存页同时列出 SKU 单价缺口和订单快照缺口，使同一根因重复出现；另有一条退货状态来源冲突导致的假快照缺口。

## 方案 A

### 商品身份

- 优先使用规范店铺的真实平台映射。
- 同一 Seller SKU 下，以标准化后的商品名称和规格名称判定业务商品身份。
- 名称与规格相同的旧合成映射、旧占位映射和真实映射视为同一商品，不触发成本键拆分。
- 商品名称或规格不同的映射继续使用 `Seller SKU [item_id:model_id]`，不得自动共享成本。

### 历史成本继承

- 精确成本键始终优先。
- 当订单身份已拆分、但旧成本只保存在原 Seller SKU 上时，仅在旧映射与当前映射的标准化商品名称及规格唯一匹配时继承。
- 无法唯一证明的记录保持待补，不用零成本或任意历史成本兜底。
- 店铺匹配始终经过 `store_aliases` 规范化，成本有效日期必须不晚于订单日期。

### 订单成本快照

- 快照以规范店铺、订单号和业务 SKU 身份逐行幂等生成。
- 已有有效成本的活跃订单应补齐 `confirmed` 快照。
- 退货状态冲突不得产生“已有 returned 快照但页面又要求 confirmed 快照”的双重状态；有效订单状态与退款状态必须采用同一条有效订单事实。

### 页面呈现

- “待补成本”主清单按缺失成本 SKU 聚合，并在条目内显示影响订单数和件数。
- 缺快照但已有成本的异常单独提示为同步异常，不与缺成本 SKU 重复列出。
- 从未成交的货架 SKU 不属于利润计算阻塞项，不进入待补成本导出；可继续计入 SKU 总数。

## 验收标准

1. 同商品的旧合成 ID 与新真实 ID 能复用旧成本。
2. `Chief 50ml` 与 `Chief 250ml` 仍使用不同成本键。
3. 线上两个已有历史成本候选只在唯一匹配成立时自动继承。
4. `moxa stick-one box` 不再显示为缺成本或缺快照。
5. 页面不重复展示同一成本缺口，未成交货架 SKU 不阻塞利润。
6. 成本、订单、库存、报表及仪表盘全量测试通过，部署后健康检查和线上只读对账通过。
