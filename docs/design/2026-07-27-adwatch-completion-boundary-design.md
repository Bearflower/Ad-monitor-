# Adwatch 全功能开发与上线边界设计

日期：2026-07-27  
状态：用户已批准

## 1. 目标

在暂不导入真实经营 CSV、暂不修改真实广告的条件下，完成蓝图 v1.2 中所有可开发、可自动测试、可影子验收的功能。开发结束后统一输出真实上线待办清单，再补经营数据、外部授权和真实页面验收。

## 2. 核心边界

系统主线保持：

```text
紫鸟 CLI 读取页面
→ SQLite
→ 利润/趋势/异常分析
→ 策略建议
→ 飞书人工审批
→ 紫鸟 CLI 操作页面
→ 审计与回滚
```

TikTok/Shopee 官方广告 API 属于 P3 可选增强，不阻塞 P0-P2 完成。P2 的真实执行方式是紫鸟 CLI 页面自动化。

“真实广告写操作”包括：

- 修改广告预算并保存；
- 修改目标 ROAS 并保存；
- 暂停或恢复广告；
- 任何会改变平台广告状态的页面提交。

它与使用 CLI 还是官方 API 无关。只要外部平台状态发生变化，就是写操作。

## 3. 三种运行模式

### Read-only

允许页面导航、数据提取、截图、分析、报告和告警。禁止点击任何会提交修改的控件。

### Shadow

执行完整的写前流程：

1. 定位店铺、Campaign 和目标控件；
2. 读取真实当前值；
3. 校验审批、熔断、变更幅度和页面状态；
4. 计算预期新值；
5. 记录 before、intended-after、截图和审计信息；
6. 在最终保存动作之前停止。

Shadow 模式不改变真实广告状态，用于验证选择器、计算、审批和审计链路。

### Live

在 Shadow 验收通过后才能启用。除 Shadow 的全部检查外，还要求：

- 有效且未过期的人工审批；
- 写操作总开关显式开启；
- 对应平台/店铺/Campaign 被加入允许清单；
- 熔断关闭；
- 当前页面值与审批时的 before 值一致；
- 动作属于允许范围；
- 写后重新读取并验证结果；
- 失败时执行可用的补偿/回滚动作并告警。

本轮开发完成时，Live 默认保持关闭。

## 4. 开发完成定义

每个功能需同时满足：

- 有明确模块边界和稳定输入输出；
- 有单元测试；
- 有集成测试或本地模拟页面测试；
- 有错误处理和审计记录；
- 能在无真实经营 CSV 时运行；
- 缺少外部依赖时显示为 `pending_external`，不得伪装成功；
- 不会意外修改真实广告。

## 5. 数据输入策略

经营数据不再阻塞采集、趋势、异常、日报和影子执行开发。

分析结果分级：

- `platform_metrics`：只依赖自动采集，可立即生成花费、GMV、订单、ROAS、CPA、趋势和基础异常。
- `estimated_profit`：导入极简成本后生成估算利润。
- `verified_profit`：退款、佣金、运费、优惠和汇率齐全后生成核验利润。
- `inventory_safe_strategy`：库存数据齐全后才允许生成加预算建议。

极简人工日输入：

```csv
data_date,total_product_cost,refund_amount
```

订单、GMV、广告花费从平台自动采集。一次性 Campaign 配置与每日数据分离。

## 6. 开发范围

### 数据与采集

- 完成 TikTok 有 Campaign 场景解析；
- Shopee SKU 明细分页与 Campaign 汇总并存；
- 单平台失败不阻塞另一平台；
- Bridge 健康检查、有限重试、自恢复尝试和失败通知；
- 退款 T+3 回溯接口；
- 库存、汇率和 SKU 映射适配器接口及模拟实现。

### 分析与策略

- 7/14/30 天窗口；
- 花费突增、ROAS 暴跌、学习期中断、库存风险；
- Webdriver 失败次数和全局低 ROAS 接入熔断；
- ROAS 目标校准、预算分配、暂停和选品建议；
- 缺成本时继续生成平台指标，但禁止声称真实利润；
- 缺库存时禁止加预算建议。

### 报告与运维

- 日报、周报、月报；
- 看板筛选、趋势、质量、审批和执行状态；
- launchd 运行前检查与失败通知；
- SQLite 自动备份和恢复校验；
- 统一运行状态和上线待办输出。

### 审批与执行

- 飞书审批卡片、签名回调服务和重放防护；
- 紫鸟 CLI Shadow Backend；
- 紫鸟 CLI Live Backend，但默认关闭；
- 预算、ROAS、暂停/恢复的动作允许清单；
- before/after 校验、截图、幂等、审计和补偿回滚；
- 删除 Campaign、账号安全和收款设置永久禁止。

### 可选增强

- TikTok Marketing API Adapter；
- Shopee API Adapter；
- API 权限缺失时标记为上线待办，不阻塞紫鸟 CLI 主线。

## 7. 外部条件与最终待办

开发结束时自动生成清单，至少包括：

- 启动并保持紫鸟客户端/Bridge 可用；
- 提供有数据的 TikTok Campaign 做选择器验收；
- 填写极简经营成本；
- 配置真实佣金、退款、汇率和库存来源；
- 配置飞书应用公网 HTTPS 回调；
- 完成 Shadow 对账；
- 逐个平台启用 Live 允许清单；
- 如需 P3 API，再提供 OAuth/API 权限；
- 完成人工回滚演练和最终上线签字。

## 8. 验收原则

- 没有真实数据不阻塞代码完成，但对应状态必须显示 `pending_data`。
- 没有 OAuth 不阻塞紫鸟 CLI 页面执行开发。
- 没有公网回调时可用本地签名回调测试完成代码验收，但真实飞书交互保持 `pending_external`。
- 所有 Live 操作默认关闭；开启必须是独立、显式、可审计的上线动作。
