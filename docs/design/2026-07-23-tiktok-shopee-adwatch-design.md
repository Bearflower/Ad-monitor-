# TikTok + Shopee 广告盯盘自动化系统设计

日期：2026-07-23  
状态：已完成方案确认，待用户复核书面规格

## 1. 目标

在一台 macOS 电脑上构建 TikTok Ads 与 Shopee Ads 的完整投放运营闭环：

1. 自动采集双平台广告与经营数据。
2. 统一数据口径并保存到本地 SQLite。
3. 计算 ROAS、CPA、利润、库存效率和趋势指标。
4. 识别异常并生成受学习期保护的策略建议。
5. 提供本地网页看板、日报、周报和飞书通知。
6. 经人工审批后执行受控的广告调整，并保留完整审计记录。

首期使用模拟数据打通完整链路；紫鸟账号和店铺配置完成后切换到真实采集器。系统不再考虑 Windows 7 迁移或兼容。

## 2. 范围与交付顺序

完整系统分四阶段连续交付，所有阶段都在本项目范围内。

### 阶段一：数据底座

- Python 项目骨架与 CLI。
- SQLite 数据库、迁移和初始化。
- TikTok、Shopee 模拟采集器。
- 紫鸟真实采集器接口及配置检查。
- 数据清洗、去重、口径转换和质量报告。
- 店铺、广告账户、Campaign 和 SKU 映射。

### 阶段二：经营分析

- ROAS、CPA、订单和 GMV 指标。
- 六层利润链路。
- 7/14/30 天趋势和异常检测。
- 学习期保护与策略建议。
- 本地网页看板。

### 阶段三：自动运营

- 每日定时采集、分析和推送。
- 日报、周报与本地归档。
- 飞书机器人通知和异常即时告警。
- 飞书失败时降级为本地 Markdown 报告。

### 阶段四：安全执行

- 飞书人工审批。
- 已批准的预算、ROAS 目标和暂停操作。
- 操作前后截图与审计。
- 熔断、幂等和失败恢复。

## 3. 总体架构

系统采用分层、可替换适配器架构：

```text
紫鸟 / TikTok / Shopee / 模拟数据
              |
        统一采集适配器
              |
      清洗、校验、去重、口径转换
              |
            SQLite
      /         |          \
   看板      分析与策略      报告
                |            |
             策略建议 ----> 飞书审批
                              |
                         安全执行器
```

模拟与真实采集器实现同一接口，向下游输出统一记录。切换数据源不得要求修改数据库、分析、报告或看板代码。

## 4. 技术选择

- 语言：Python。
- 数据库：SQLite，本地单文件存储。
- 配置：环境变量加非敏感配置文件。
- CLI：Python 模块入口 `python -m adwatch`。
- 看板：本地 Web 服务，具体框架在实施计划中根据依赖兼容性选择。
- 调度：进程内调度器，并提供可由 macOS `launchd` 调用的单次任务命令。
- 测试：单元测试、数据库集成测试和端到端模拟测试。

SQLite 选择基于当前单机部署和低运维要求。项目不依赖本机已安装但未运行的 MySQL 9.4。

## 5. 模块边界

### `collectors`

负责从模拟数据或紫鸟浏览器获取原始记录。每个平台独立失败、独立重试，不阻塞另一平台。

### `pipeline`

负责字段映射、类型转换、币种规范、去重、质量校验和隔离无效记录。禁止在此模块计算策略。

### `storage`

负责 SQLite 连接、事务、迁移和仓储接口。业务模块不直接拼接 SQL。

### `analytics`

负责聚合指标、利润链路、时间窗口和异常检测。输入是已通过质量校验的数据。

### `strategy`

负责根据分析结果、库存、学习期和阈值生成建议。只生成建议，不直接执行广告操作。

### `approval`

负责创建审批任务、发送飞书审批卡片、验证回调并记录审批人和审批结果。

### `executor`

只消费已批准且未过期的建议。负责幂等校验、风控复核、执行、截图和审计。

### `reporting`

负责日报、周报、飞书通知和本地 Markdown 降级报告。

### `dashboard`

负责只读数据展示及允许调整非敏感策略阈值。广告写操作仍必须进入审批流。

### `scheduler`

负责任务编排、互斥、重试和运行记录，不包含采集或分析业务逻辑。

## 6. 数据模型

主要实体和用途如下：

| 实体 | 用途 |
| --- | --- |
| `stores` | 平台、店铺、站点和币种 |
| `ad_accounts` | 店铺对应的广告账户 |
| `campaigns` | Campaign、状态、目标 ROAS、预算及学习期 |
| `sku_mappings` | TikTok Product ID、Shopee 商品 ID 与统一 SKU |
| `daily_ad_metrics` | 每日花费、GMV、订单、ROAS、CPA 等原始和统一指标 |
| `order_attribution` | 订单归因、取消、退款及归因窗口 |
| `inventory_snapshots` | 库存、在途库存和缺货风险 |
| `product_costs` | 商品成本、佣金、运费、优惠券和固定成本分摊 |
| `exchange_rates` | 原币种到人民币的日期汇率 |
| `profit_results` | 净销售额、毛利、净利润和盈亏平衡 ROAS |
| `alerts` | 异常类型、严重度、状态和证据 |
| `recommendations` | 策略动作、原因、前后值和风险级别 |
| `approvals` | 审批状态、审批人、时间和回调标识 |
| `execution_audits` | 执行请求、结果、截图和回滚信息 |
| `collection_runs` | 每次采集的来源、状态、耗时和错误 |
| `quality_checks` | 数据质量规则、结果和隔离数量 |
| `quarantined_records` | 不参与分析的无效原始记录 |
| `system_settings` | 非敏感阈值与系统开关 |

`daily_ad_metrics` 使用平台、店铺、账户、Campaign、SKU、数据日期和归因口径组成稳定幂等键。重复采集必须更新同一逻辑记录，不得累加重复行。

## 7. 统一指标和利润口径

- `roas = attributed_gmv / spend`，花费为零时结果为空而不是无穷大。
- `cpa = spend / attributed_orders`，订单为零时结果为空。
- `net_sales = gmv - refunds`。
- `gross_profit = net_sales - platform_commission - product_cost`。
- `net_profit = gross_profit - ad_spend - seller_shipping - coupons - allocated_fixed_cost`。
- 所有跨平台人民币汇总必须使用与数据日期对应的汇率。
- 平台原始 GMV、订单和归因窗口必须保留，不用统一值覆盖原始值。
- 退款允许 T+3 回溯修正，修正后重算受影响日期的利润和告警。

## 8. 策略与学习期

- TikTok 默认学习期为 7 天，Shopee 默认学习期为 14 天。
- 学习期内不生成暂停建议；预算调整建议幅度不超过 ±20%。
- 学习期结束后，连续 3 天 ROAS 低于目标 50% 才可建议暂停。
- ROAS 低于目标 70% 且已过学习期，可建议单次减预算不超过 30%。
- ROAS 高于目标且库存充足，可建议单次加预算不超过 30%，累计预算不超过基准预算两倍。
- 负利润、高退款或缺货风险商品不得生成加预算建议。
- 利润和现金回收优先于 ROAS。
- 所有阈值可配置，修改必须记录操作者、旧值和新值。

## 9. 权限和风控

### 自动允许

- 数据采集、分析、报告和异常告警。
- 操作前后截图。

### 必须人工确认

- 单条广告预算调整。
- ROAS 目标调整。
- 暂停低效广告。

### 永久禁止自动执行

- 大额加预算，定义为相对当前预算增加超过 50%。
- 新建大规模 Campaign。
- 删除广告、广告组或 Campaign。
- 修改收款、账号、店铺或安全设置。

执行器必须在执行前再次校验审批未过期、建议未被替代、当前值仍与审批时一致、未处于熔断状态。任何校验失败都终止执行并留下审计记录。

## 10. 熔断与恢复

以下任一条件触发写操作熔断：

- 当日异常告警达到 5 条。
- 紫鸟 Webdriver 连续失败 3 次。
- 核心数据质量检查失败。
- 连续 2 天全平台 ROAS 低于目标的 60%。

熔断后仍允许采集、分析和报告，但禁止广告写操作。恢复需要人工确认，并记录恢复人和原因。

采集和报告任务支持有限次数重试、断点续跑和幂等执行。单个平台失败不阻塞另一平台。飞书连续失败后保存本地 Markdown，并在控制台和运行日志中标记降级状态。

## 11. CLI 设计

```bash
python -m adwatch init
python -m adwatch doctor
python -m adwatch collect --mode mock
python -m adwatch collect --mode ziniao
python -m adwatch analyze
python -m adwatch report daily
python -m adwatch report weekly
python -m adwatch dashboard
python -m adwatch run daily
python -m adwatch schedule
```

`run daily` 按顺序执行采集、质量校验、分析、策略生成、日报和通知。任一步骤的状态均写入运行记录。

## 12. 配置与安全

- 紫鸟账号、密码、飞书 Webhook 和回调密钥只从本机环境变量读取。
- 仓库提供 `.env.example`，真实 `.env` 必须被 Git 忽略。
- 日志不得打印密码、Cookie、Token、完整 Webhook 或浏览器身份信息。
- SQLite 文件、截图、原始下载报表和报告统一放入运行数据目录，并默认被 Git 忽略。
- 模拟模式生成的所有页面和报告必须显示“模拟数据”标记。
- 未配置真实采集器时，显式执行 `--mode ziniao` 必须失败并给出配置说明；不得静默改用模拟数据。

## 13. 错误处理

- 未知币种、非法负数、主键字段缺失和无法解析的日期进入隔离表，不参与分析。
- 外部页面结构变化必须返回可定位的采集错误，并保存允许范围内的截图。
- 数据库写入以批次事务完成，失败时回滚该批次。
- 任务错误包含稳定错误码、用户可读消息和内部诊断信息。
- 所有重试使用上限和退避策略，避免无限循环。

## 14. 看板和报告

看板至少支持：

- 平台、店铺、Campaign、SKU 和日期筛选。
- 花费、GMV、ROAS、CPA、毛利、净利润和库存风险。
- 7/14/30 天趋势。
- TOP3、BOTTOM3、异常、建议、审批和执行状态。
- 采集运行状态与数据质量结果。

日报至少包含：

- TikTok 与 Shopee 昨日花费、ROAS、订单、GMV 和学习期广告数。
- 异常告警。
- TOP3、BOTTOM3 商品及建议。
- 数据来源、采集时间和质量状态。

周报增加趋势、利润、实验和操作影响复盘。

## 15. 测试与验收

### 自动化测试

- 指标和利润公式边界测试。
- 学习期、连续天数、预算限制和熔断规则测试。
- SQLite 迁移、事务和幂等测试。
- 双平台模拟采集契约测试。
- 日报渲染和飞书失败降级测试。
- 审批过期、状态漂移和重复执行测试。
- 一条命令完成模拟端到端流程的测试。

### 首期验收

- `python -m adwatch run daily --mode mock` 可完成双平台模拟采集、分析、建议、日报和本地输出。
- 重复运行不会产生重复指标或重复执行记录。
- 模拟异常能触发告警、审批任务和熔断。
- 看板可查看所有规定维度和核心指标。
- 调度任务可运行，失败时有明确日志和降级产物。

### 真实数据验收

紫鸟配置完成后，连续 3 天将后台人工数据与采集结果比对。花费、GMV、订单和 Campaign 状态等核心字段准确率不低于 99%，差异必须可追溯到归因窗口、时区、退款回溯或平台展示延迟。

## 16. 非目标

- 首版不依赖 TikTok Marketing API 或 Shopee 官方写 API。
- 不实现未经人工审批的广告写操作。
- 不实现广告、广告组或 Campaign 删除。
- 不支持 Windows 7 部署。
- 不以大语言模型替代确定性的指标计算、权限校验或风控规则。
