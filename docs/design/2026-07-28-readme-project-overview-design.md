# README 项目功能简介设计

## 目标

将 README 重构为面向 GitHub 访客的项目功能简介：

- 以产品能力和业务价值为主，让读者快速理解系统解决什么问题。
- 以精简技术摘要为辅，说明架构、安全设计和启动方式。
- 不写成长篇操作手册，不复制完整上线流程。

## 文档结构

1. 一句话项目定位。
2. 系统解决的业务问题。
3. 核心功能模块：
   - TikTok/Shopee 广告数据采集；
   - 订单与 SKU 成本；
   - 货盘代发和自有库存双履约模式；
   - 收入、费用、采购、广告资金和合伙人分润；
   - 利润与三种 ROAS；
   - 广告异常、建议、审批和安全执行；
   - 三日对账、质量报告、备份和本地看板。
4. 端到端业务流程。
5. 安全边界和当前写操作状态。
6. 精简架构和技术栈。
7. 快速启动与常用命令。
8. 当前真实进度和待激活能力。

## 审批说明

- 只在功能列表和安全边界中简要说明审批能力。
- 飞书公网回调标记为“代码已具备、现场暂缓启用”。
- 明确批准只改变审批状态，真实广告修改仍由独立执行链路触发。
- 不展开公网适配层部署教程。

## 上线状态表达

README 使用简短状态表区分：

- 已完成：代码、SQLite、紫鸟授权、Shopee 真实采集、订单成本和首日对账。
- 现场激活中：Shadow、回滚演练、选择器、三日对账、Live 白名单。
- 等待真实数据：TikTok 有数据 Campaign。
- 暂缓或可选：飞书公网回调、官方 API OAuth。

不得用模拟数据、空 Campaign 或手工设置状态冒充现场验收完成。

## 验证与发布

- 核对 README 中的命令均存在于 CLI 参数解析器。
- 核对环境变量均存在于 `.env.example` 和 `Settings`。
- 运行全量 pytest、Ruff 和 `git diff --check`。
- 仅提交 README 和本设计修订，不纳入用户未跟踪文件。
- 将测试通过的本机 `main` 直接推送到已配置的 `origin/main`。
