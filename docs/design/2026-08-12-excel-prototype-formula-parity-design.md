# Excel 原型公式等价收口设计

**日期：** 2026-08-12

**状态：** 已批准

**原型：** `Shopee_tiktok泰国店记账.xlsx`

## 1. 背景与目标

原型工作簿由 11 张可见工作表组成：收支总览、收入明细、进货成本、
出库产品、费用支出、广告充值、刷单成本、月度汇总、合伙人分润、
汇率换算和前期投入。它不仅定义了页面和字段，也通过公式定义了从明细
录入到月度、年度和分润结果的联动规则。

本轮目标不是机械复制 Excel 界面，而是在 AdWatch 中实现可审计的公式
等价闭环：用户录入或平台同步一条经营事实后，系统自动完成原币换算、
月份归集、年度汇总、经营利润计算和分润余额更新；历史事实保留其原币、
采用汇率、人民币结果、来源和状态。

## 2. 已确认范围

### 2.1 纳入

- 原币金额、币种、汇率和人民币金额的完整留痕；
- 按发生月份自动解析汇率，允许有审计记录的人工月度覆盖；
- 收入、采购、销售出库、经营费用、广告资金、广告消耗、刷单成本和
  合伙人投入的统一经营汇总；
- 本月、12 个月、年度总览；
- 分润期间的净利润、逐人应分、已支付、未支付和结清状态；
- 采购物流/到货信息与订单出库物流/发货信息的查询展示；
- 现有表和服务的向后兼容迁移；
- 历史 Excel 导入的预览和重复检测契约，但本轮不未经确认写入历史数据。

### 2.2 保持不变

- TikTok 真实自动采集继续关闭；历史 TikTok 数据与人工平台分类仍可保留；
- 真实广告写入继续关闭；
- SQLite 仍是唯一业务事实源；
- 已确认/已结账事实不得因后来修改汇率或成本而静默改写；更正通过版本、
  冲销或显式重算完成；
- 平台同步事实优先，人工输入通过调整或人工来源事实补充，不覆盖平台原始行。

### 2.3 不纳入

- 自动导入原型工作簿中的历史记账数据；
- 官方 TikTok/Shopee OAuth/API；
- Live 广告写操作；
- 多企业、多租户、复杂仓储批次和订单到采购批次的强制追踪；
- 仅为清空旧路线图而扩展实验、广告策略等与记账原型无关的功能。

## 3. 方案选择

### 方案 A：机械复刻 Excel 公式

优点是表面结果与原型最接近；缺点是会继承两个会计问题：采购付款和销售
成本重复扣减，以及广告充值和实际广告消耗混同。以后换汇率还会静默改变
已确认历史结果。

### 方案 B：公式等价、会计口径修正（采用）

保留 Excel 的输入与自动联动体验，将每个单元格公式转为领域计算和查询；
同时把采购、广告充值分别归入现金/资产，把销售成本、广告实际消耗归入
损益。已确认历史保存采用汇率和人民币金额，保证可追溯。

### 方案 C：只补 Web 展示

开发量较小，但底层数据仍缺原币和自动汇率，月表、年表、分润不能从同一套
事实重算，无法达到公式等价要求，因此不采用。

## 4. 统一金额与汇率规则

### 4.1 金额事实

所有跨币种人工事实至少保存：

- `amount_original`：原币金额；
- `currency`：规范币种代码 `CNY`、`THB`、`SGD`；
- `rate_to_cny`：一单位原币折合人民币；
- `amount_cny`：`amount_original × rate_to_cny`，人民币保留两位小数；
- `rate_date`、`rate_source`：采用汇率日期和来源；
- `occurred_on`、`created_by`、`created_at`、`status`。

币种符号兼容映射为：`¥/￥/CNY → CNY`、`฿/THB → THB`、
`S$/SGD → SGD`。CNY 的汇率恒为 1。

### 4.2 月度汇率

新增月度汇率覆盖事实，键为 `(currency, year_month)`，保存人民币直汇率、
来源、备注和审计信息。页面同时展示：

- CNY → THB；
- THB → CNY；
- SGD → CNY。

CNY→THB 与 THB→CNY 互为倒数，但数据库权威值统一保存 `rate_to_cny`。
解析优先级为：

1. 该月份人工覆盖；
2. 发生日精确日汇率；
3. 发生日前最近且不超过允许陈旧天数的日汇率；
4. 无可用汇率时拒绝确认并显示待补汇率，禁止默认为 0 或 1。

草稿可跟随月度覆盖重新预览；事实一旦确认，采用汇率和人民币金额被冻结。

## 5. Excel 工作表等价映射

### 5.1 收入明细

原型字段：日期、平台、订单编号、收入 SGD、备注。

系统实现：平台同步继续写入不可变 `settlement_records`；人工收入补录新增
结构化入口，保存平台、店铺、订单号、原币、汇率、人民币金额、说明和来源。
人工补录生成独立收入调整，不覆盖同订单的平台结算。平台、店铺、订单号和
来源键用于重复检测。

等价公式：

```text
人民币收入 = 原币收入 × 采用汇率
月收入 = Σ 当月已确认人民币结算 + Σ 当月有效收入调整
```

### 5.2 进货成本

原型公式为数量乘单价，再按发生月汇率折算。采购模型扩展为：产品名称、SKU、
供应商、数量、原币单位价、币种、汇率、人民币单位成本/行金额、物流单号、
到货状态和备注。

```text
原币行金额 = 数量 × 原币单位价
人民币采购金额 = 原币行金额 × 采用汇率
```

采购确认后生成采购入库和现金流；它增加库存资产，不直接进入经营利润。
采购金额仍在月度经营账中作为“采购现金支出/备货投入”单独展示。

### 5.3 出库产品

平台订单、有效 SKU 成本和履约方式自动生成订单成本快照。自有备货订单生成
销售出库；货盘代发订单不扣本地库存，但保存订单成本。取消单不出库，退货按
物流事实回库或报损。

出库查询需展示日期、订单、产品、SKU、数量、单位成本、总成本、物流状态和
可用的物流单号。单位成本快照确认后不会被后来修改 SKU 成本静默覆盖。

```text
订单销售成本 = Σ 已确认订单成本快照
```

### 5.4 费用支出

沿用费用草稿、确认和冲销流程。录入日期与币种后由系统自动建议汇率，用户可
选择月度覆盖或提交有理由的行级汇率；确认后冻结。月度汇总按费用类别、币种、
付款人和资金性质提供分组结果。

只有 `affects_profit=1` 的已确认费用进入经营利润；资本投入、代垫和资金调整
不得误扣利润。

### 5.5 广告充值

扩展广告资金事实，分别保存：

- 支付/充值原币金额；
- 平台实际到账原币金额；
- 币种、汇率和两者人民币金额；
- 平台、店铺、资金类型、来源、截图/凭证。

现金流以实际支付金额为准，广告预付余额以实际到账金额为准；赠送只增加广告
余额，不减少现金；退款按实际退回现金和余额变化处理。广告充值不进入损益，
只有 `ad_spend_entries` 的实际广告消耗进入利润和 ROAS。

### 5.6 刷单成本

扩展为货款原币、服务费原币、币种、采用汇率及各自人民币金额：

```text
刷单成本 CNY = (货款原币 + 服务费原币) × 采用汇率
```

刷单成本进入经营利润；关联订单/SKU 继续从真实销售和广告归因指标中排除。

### 5.7 前期投入

前期投入不恢复为独立会计表，而是在出资/代垫入口保留投入项目、出资人、
原币金额、币种、汇率、人民币金额和备注。按共同、洁云、苏姐及其他出资人
汇总。出资影响现金和出资对账，不进入经营利润。

### 5.8 月度汇总与年度总览

新增统一 `OperatingStatementService`，同一计算结果供 Dashboard、月报、年报
和分润使用，禁止各页面复制不同 SQL。

每月输出至少包括：

- 结算收入；
- 采购现金支出；
- 销售成本；
- 平台费；
- 广告充值支付、实际到账与实际消耗；
- 刷单成本；
- 其他经营费用；
- 净利润；
- 资本投入与提款；
- 经营现金净变动；
- 数据完整性状态与待补项。

正确损益公式为：

```text
经营净利润
= 结算收入 + 有效收入调整
- 销售成本
- 平台费
- 广告实际消耗
- 经营费用
- 刷单成本
```

采购付款、广告充值、资本投入和提款只进入现金/资产视图，不再次进入损益。
年度总览为同一自然年 12 个月人民币结果之和，并支持选择年份；不硬编码 2026。

### 5.9 合伙人分润

分润期间必须读取统一经营汇总服务的净利润，禁止维护第二套利润 SQL。期间
生成时保存计算快照与输入范围，确认后锁定。

```text
可分配利润 = max(期间净利润, 0)
个人应分 = 可分配利润 × 期间生效协议比例
个人已付 = Σ 已支付记录 + Σ 支付冲销记录
个人未付 = max(个人应分 - 个人已付, 0)
```

期间状态规则：

- `draft`：已生成，待确认；
- `ready`：已确认且尚未支付；
- `paying`：至少一人已支付但仍存在未付余额；
- `settled`：所有人的未付余额均为 0；
- `loss`：期间净利润不大于 0，无可分配金额；
- `reversed`：期间已冲销。

负利润保留为经营结果，但不生成负分润债务。本轮不自动跨期抵扣亏损；若以后
需要累计亏损结转，应作为独立批准的会计策略版本实现。

## 6. 页面与交互

### 6.1 今日经营

在现有日经营和趋势之上增加：本月经营总览、所选年度总览、当前月汇率卡、
月度完整性提示。所有数值可下钻到对应明细页。

### 6.2 收入与广告资金

增加结算收入明细、人工收入补录、广告充值双金额表单、原币与人民币并列展示、
月度汇率自动建议及凭证入口。

### 6.3 SKU 与库存

采购表单补齐原币、汇率、产品、物流和到货状态；增加订单出库明细表。已有
履约方式、SKU 成本版本、库存流水、冲销和凭证继续保留。

### 6.4 记账对账

补充月度汇率维护、刷单多币种、出资多币种和分类汇总；危险修改继续采用冲销
或新版本，不提供直接覆盖已确认事实的入口。

### 6.5 月度经营账

新增独立 Web 页面，默认展示所选年度 12 个月，与 Excel `月度汇总` 等价；
年度合计固定使用同一批月度结果求和，并展示利润口径说明。

### 6.6 合伙人分润

期间列表展开显示每位合伙人的比例、应分、已支付、未支付和状态；页面提供
期间级总览和累计总览，支付或冲销后即时重算状态。

## 7. 数据迁移与兼容

采用只增不删的 SQLite 迁移：

- 为采购、广告资金、刷单、出资等表补齐原币和汇率字段；
- 既有只存 CNY 的记录回填为 `currency='CNY'`、`rate_to_cny='1'`，金额不变；
- 新增月度汇率覆盖、结构化人工收入及必要物流字段；
- 不覆盖平台结算、订单、库存和利润历史事实；
- 所有新字段的默认值只用于旧记录迁移，新建记录必须经过业务校验；
- 迁移后运行 `PRAGMA integrity_check` 和公式等价回归样本。

## 8. Excel 历史数据导入边界

本轮实现预览和重复检测契约，但不自动落库。预览结果按工作表显示有效、重复、
冲突、缺汇率和缺字段行。候选重复键包括：

- 收入：平台 + 店铺 + 订单号 + 日期 + 金额；
- 采购：采购单号 + SKU，缺采购单号时使用来源文件哈希 + 行号；
- 广告资金：平台 + 店铺 + 日期 + 支付金额 + 实际到账；
- 刷单：平台 + 店铺 + 订单号 + SKU；
- 费用/投入：日期 + 类别/项目 + 付款人/出资人 + 原币金额 + 币种。

只有用户另行确认导入批次后才允许写入，并生成导入事件和可回滚批次。

## 9. 错误处理与完整性

- 缺汇率、无效币种、负数量、零金额和不平衡分润协议在确认前阻断；
- 草稿允许缺少非关键凭证，但不得进入正式月度损益；
- 页面显示具体待补项，禁止把缺失金额自动当作 0；
- 收入、成本和费用的状态过滤在统一服务中集中定义；
- 月度汇总返回来源计数和计算版本，便于定位为何与 Excel 或平台不同；
- 对同一期间重复生成分润草稿进行冲突检查，防止重复分配。

## 10. 测试与验收

### 10.1 公式等价样本

用一个不含敏感信息的小型样本覆盖 CNY、THB、SGD，逐条断言：

- 数量乘单价及汇率折算；
- 费用、广告资金、刷单、投入的原币到 CNY；
- 月份边界和年度求和；
- 月度汇率覆盖优先级及确认后冻结；
- 采购和广告充值不进入利润；
- 销售成本和广告实际消耗只扣一次；
- 60%/40% 应分、部分支付、全部支付、冲销和亏损期状态。

### 10.2 回归与安全门禁

- 每个服务和路由先写失败测试，再写最小实现；
- 迁移兼容旧数据库并验证幂等；
- Dashboard 关键页面包含原币、汇率、月/年汇总和分润余额；
- 全量 pytest、Ruff、compileall、`git diff --check` 全部通过；
- 代码审查重点检查重复扣减、状态过滤、汇率冻结、重复导入和既有数据兼容；
- 部署包排除 `.env`、数据库、日志、凭证、临时文件和原型工作簿；
- 生产部署后只读检查容器健康、迁移版本、核心页面、数据库完整性和一组已知
  月份的汇总来源，不擅自导入 Excel 历史数据。

## 11. 实施分批

1. 统一汇率解析、金额值对象及兼容迁移；
2. 收入、采购、广告资金、刷单和投入的原币字段与服务；
3. 统一经营汇总服务及公式等价测试；
4. 本月/年度总览和月度经营账页面；
5. 分润分配、余额和状态闭环；
6. Excel 历史导入预览/查重契约；
7. 全量回归、审查、安全打包与生产部署验收。

每批必须保持现有 Shopee 采集、利润重算、库存成本、调度和生产页面兼容；
TikTok 自动采集和 Live 广告写入不得因本轮开发被重新启用。
