# `/inventory` 待补 SKU 成本清单改版设计

**日期：** 2026-08-04  
**状态：** 已确认，待实施

## 目标

将 `/inventory` 的“待补 SKU 成本”从宽表格改成无需横向滚动的紧凑清单，同时保留逐个 SKU 直接补录成本的能力。桌面端优先提高扫描效率，窄屏端保持完整可操作，不隐藏关键字段。

## 设计选择

采用“紧凑清单 + 单行展开编辑”，不继续使用宽表格，也不使用多列卡片网格。

- 默认态只展示 SKU、平台/店铺、订单数、缺成本件数、最近订单日期和“补录成本”按钮。
- 点击“补录成本”只展开当前条目的编辑区；其他条目保持紧凑。
- 编辑区展示成本生效日期、单位成本、备注和保存按钮。
- 表单仍提交到现有 `/sku-costs` 路由，服务端业务逻辑与数据口径不变。
- 页面不引入前端框架，使用原生 `<details>/<summary>` 提供展开、键盘操作和无 JavaScript降级能力。

## 信息结构

每个待补 SKU 使用一个独立条目：

1. 左侧主信息：Seller SKU，允许自然换行，长哈希类 SKU 使用可断行规则。
2. 次级信息：平台与店铺以低强调标签展示。
3. 数量指标：订单数、缺成本件数、最近订单日期使用紧凑的三列指标区。
4. 右侧动作：“补录成本”作为 `<summary>` 的可点击文案；展开时改为清晰的编辑状态。
5. 展开区：表单使用响应式网格；日期、成本、备注、保存按钮在宽屏横向排列，在窄屏纵向排列。

## 视觉规范

- 延续当前 Dashboard 的蓝色主色和浅色表面，不新建另一套主题。
- 清单条目使用 12px 圆角、1px 语义边框和轻微悬停背景；不使用厚重阴影。
- SKU 使用 600 字重；数量使用等宽数字；标签与帮助文本保持足够对比度。
- 输入框和按钮高度至少 44px；键盘焦点使用清晰的主色轮廓。
- 动画仅用于展开状态的颜色/边框反馈，时长 150–200ms，并尊重 `prefers-reduced-motion`。

## 响应式行为

- `>= 1024px`：摘要使用“主信息 + 三项指标 + 动作”的单行网格；展开表单为四列。
- `768–1023px`：摘要的指标自动换到第二行；展开表单为两列。
- `< 768px`：所有区域单列堆叠，按钮占满可用宽度。
- 清单容器和条目禁止产生水平溢出；长 SKU 使用 `overflow-wrap:anywhere`。
- 移除当前 `.inline-cost-form` 的固定 `min-width:560px`，不依赖 `.table-wrap` 横向滚动。

## 数据流与错误处理

- 服务端继续通过 `InventoryService.list_missing_sku_costs()` 生成条目。
- 隐藏字段继续传递 CSRF、platform、store、seller_sku。
- `effective_date` 默认使用 `first_missing_date`，确保补录版本能覆盖最早缺成本订单。
- 表单提交成功仍重定向回 `/inventory`；失败继续使用现有路由的 HTTP 错误响应，本次不扩大为 Toast 或局部提交。
- 取消订单过滤、成本版本判断和待补数量计算均不改变。

## 可访问性

- 使用原生 `<details>/<summary>`，支持键盘 Enter/Space、展开状态和屏幕阅读器语义。
- 每个表单字段使用可见 `<label>` 并通过 `for`/`id` 关联，不再只依赖 placeholder 或 aria-label。
- 每个条目的按钮文案包含对应 SKU 的可访问名称，避免 15 个相同“补录成本”按钮难以区分。
- 颜色不作为唯一状态信号；展开条目同时通过文案和结构表达状态。

## 测试与验收

### 自动测试

- 页面渲染 15 条数据时生成 15 个 `<details>` 条目和 15 个 `/sku-costs` 表单。
- 不再渲染待补成本宽表格，也不包含 `min-width:560px`。
- 长 SKU 存在可断行样式，容器存在 `min-width:0` 和无水平溢出约束。
- 每个成本字段都有可见 label，CSRF 和预填日期保持正确。
- 现有成本提交路由测试继续通过。

### 浏览器验收

- 在当前桌面窗口无需横向滚动即可看到完整摘要和动作。
- 依次验证 1440px、1024px、768px、375px 视口无水平溢出。
- 展开任意一条时只有该条显示编辑区；输入框与保存按钮均可见且可键盘聚焦。
- `ST-OC1232-08A` 仍不出现在清单中。

## 非目标

- 不新增批量成本录入。
- 不改变 SKU 成本后端规则、数据库迁移或订单同步。
- 不重做整个 `/inventory` 页面和其他业务模块。
- 不在本次引入 JavaScript 状态管理或前端框架。
