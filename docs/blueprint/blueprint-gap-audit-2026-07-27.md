公网 HTTPS 或连续运行证据的上线验收项。真实广告写入保持关闭。

## 真实广告修改的边界

系统的分析与推荐不需要写权限。修改广告时，确实是通过紫鸟 CLI 控制
真实店铺页面，但“能控制页面”不等于可以安全提交。Live 还必须具备：

1. 已批准且未过期的建议；
2. 当前页面值与审批时预期值一致；
3. 熔断器关闭；
4. 全局写开关和精确目标白名单同时放行；
5. 提交前后审计及失败回滚；
6. 对该平台真实页面选择器完成现场核验。

因此当前代码具备 Shadow 和 Live 安全边界以及现场激活门禁，但
`ADWATCH_LIVE_WRITES=false`。未完成真实页面核验前，不会提交广告修改。

## 最小人工维护数据

日常不再要求手工逐单录入订单。系统先从平台订单生成待补 SKU 清单，
用户主要填写 `平台、店铺、Seller SKU、生效日期、人民币单位成本`。
同一订单多个 SKU 或同 SKU 多件由订单明细自动聚合，成本按数量计算并
冻结到订单快照。费用、采购、出资、提款和分润实付等平台无法获知的
事实在本地 Web 维护。

佣金、商家运费、优惠、退款、汇率和目标 ROAS 若平台或适配器尚未提供，
仍会被列为待补事实；系统不会把缺失值当作零，也不会在多 Campaign
场景猜测分摊。
